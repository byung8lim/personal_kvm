# 퍼스널 KVM 서비스 설치·구성 및 사용 가이드

이 문서는 `personal-kvm-service-v0.0.6`을 Rocky Linux 9.8 또는 10.x KVM 호스트에 설치하고 운영하기 위한 절차다. 명령은 별도 표기가 없으면 설치 대상 호스트에서 실행한다.

> 중요: 설치 과정은 NetworkManager, libvirt, MySQL, Nginx, 방화벽과 물리 NIC 구성을 변경한다. 원격 서버에서 잘못된 브리지 값을 사용하면 SSH 연결이 끊길 수 있다. 콘솔 접근이 가능한 격리 호스트에서 먼저 검증한다.

## 1. 설치 전 준비

### 1.1 필수 조건

- Rocky Linux 9.8 또는 10.x
- Intel VT-x 또는 AMD-V가 활성화된 x86_64 CPU
- root 또는 `sudo` 권한
- 루트 파일시스템 여유 공간 5GB 이상
- VM 이미지·루트 디스크용 `/data`, 추가 디스크용 `/data2`
- 외부 브리지에 사용할 물리 NIC, 호스트 IP/CIDR, 기본 게이트웨이
- 설치 중 패키지를 내려받을 인터넷 연결
- 운영 환경에서는 호스트명과 일치하는 TLS 인증서와 개인키

사전 확인:

```bash
cat /etc/os-release
grep -E '(vmx|svm)' /proc/cpuinfo | head
df -h /
ip -brief link
ip -4 address
ip route
```

## 2. 반드시 결정해야 하는 비밀번호와 비밀값

설치 전에 아래 값을 정한다. 실제 값은 문서, 셸 히스토리, Git 저장소에 기록하지 않는다.

| 항목 | 설정 위치/방법 | 필수 기준 |
| --- | --- | --- |
| 웹 관리자 아이디 | 설치 시 `PKVM_ADMIN_USER` | 기본값은 `admin`; 운영 환경에서는 별도 이름 권장 |
| 웹 관리자 초기 비밀번호 | 설치 시 `PKVM_ADMIN_PASS` | 12자 이상, 대문자·소문자·숫자·특수문자 포함 |
| MySQL `pkvm_user` 비밀번호 | `/etc/personal-kvm/.env`의 `DB_PASSWORD`와 `DATABASE_URL` | 설치 스크립트가 난수 생성; 두 값은 반드시 일치 |
| JWT 서명키 | `/etc/personal-kvm/.env`의 `JWT_SECRET_KEY` | 설치 스크립트가 난수 생성; 외부 공유 금지 |
| TLS 개인키 | 설치 시 `PKVM_TLS_KEY` | 암호화되지 않은 PEM 키를 root만 읽을 수 있게 보관 |
| 게스트 OS 계정/비밀번호 | `config/config.yaml`의 `service.default_vm_user`, `default_vm_password` | 현재 기본 비밀번호를 운영에 사용하지 말 것 |

### 2.1 관리자 초기 비밀번호를 안전하게 입력하는 방법

명령줄에 비밀번호를 직접 적으면 셸 히스토리에 남을 수 있다. 다음처럼 숨김 입력으로 환경변수를 설정한다.

```bash
read -rsp '초기 관리자 비밀번호: ' PKVM_ADMIN_PASS
echo
export PKVM_ADMIN_PASS
export PKVM_ADMIN_USER='pkvm-admin'
```

비밀번호 요구사항은 다음과 같다.

- 길이 12~128자
- 영문 대문자 1자 이상
- 영문 소문자 1자 이상
- 숫자 1자 이상
- 특수문자 1자 이상
- 변경 시 기존 비밀번호와 다른 값

설치 후 최초 로그인에서 반드시 새 비밀번호로 변경한다. 초기 비밀번호 변경 전에는 대부분의 관리 API가 차단된다.

### 2.2 게스트 기본 비밀번호

배포본의 `config/config.yaml`에는 예제 게스트 비밀번호가 들어 있으므로 설치 전에 반드시 교체한다.

```yaml
service:
  default_vm_user: "kvmadmin"
  default_vm_password: "여기에_운영용_강한_임시비밀번호"
```

현재 공통 프로비저닝 경로는 SSH 호스트키 생성과 hostname 적용을 중심으로 동작한다. 게스트 이미지별 계정/비밀번호 적용 여부는 실제 이미지 부팅 후 확인하고, 가능하면 비밀번호 로그인보다 `/var/lib/personal-kvm/.ssh/id_rsa.pub` 기반 SSH 키 인증을 사용한다.

## 3. 네트워크와 스토리지 구성

설치 전에 `config/config.yaml`을 환경에 맞게 수정한다.

### 3.1 스토리지

```yaml
storage:
  image_dir: "/data/images"
  root_disk_dir: "/data/instances"
  extra_disk_dir: "/data2/disks"
```

- 모든 경로는 절대경로여야 한다.
- `/data`와 `/data2`를 별도 파일시스템으로 사용할 경우 설치 전에 마운트하고 `/etc/fstab`에 등록한다.
- 설치 후 관리 디렉터리는 `pkvm:kvm`, 권한 `0770`으로 설정된다.
- 제거 스크립트는 `/data/instances`, `/data2/disks`, `/data/images`의 관리 파일을 삭제하므로 전용 경로만 사용한다.

### 3.2 네트워크

각 네트워크의 CIDR과 IP 풀은 서로 겹치면 안 된다. 게이트웨이·네트워크·브로드캐스트 주소를 풀 범위에 포함하지 않는다.

```yaml
networks:
  bridged:
    bridge_name: "virbr0"
    physical_nic: "enp3s0"
    host_ip_cidr: "192.168.0.6/24"
    cidr: "192.168.0.0/24"
    gateway: "192.168.0.1"
    pool_start: "192.168.0.101"
    pool_end: "192.168.0.200"
  nat:
    bridge_name: "virbr1"
    cidr: "10.10.50.0/24"
    gateway: "10.10.50.1"
  internal:
    bridge_name: "virbr2"
    cidr: "10.10.60.0/24"
  management:
    bridge_name: "virbr3"
    cidr: "10.10.70.0/24"
    host_bind_ip: "10.10.70.1"
```

설치 변수의 값은 `config.yaml`의 bridged 설정과 일치시킨다.

```bash
export PKVM_PHYS_NIC='enp3s0'
export PKVM_HOST_BR_IP='192.168.0.6/24'
export PKVM_HOST_BR_GW='192.168.0.1'
```

원격 설치라면 다음 값을 특히 확인한다.

```bash
ip link show "$PKVM_PHYS_NIC"
python3 -c "import ipaddress; print(ipaddress.ip_interface('$PKVM_HOST_BR_IP')); print(ipaddress.ip_address('$PKVM_HOST_BR_GW'))"
ping -c 3 "$PKVM_HOST_BR_GW"
```

## 4. TLS 인증서 구성

### 4.1 운영 인증서 사용

인증서와 개인키를 설치 패키지 외부의 안전한 위치에 준비한다.

```bash
sudo openssl x509 -in /secure/path/server.crt -noout -subject -issuer -dates
sudo openssl pkey -in /secure/path/server.key -check -noout
export PKVM_TLS_CERT='/secure/path/server.crt'
export PKVM_TLS_KEY='/secure/path/server.key'
```

두 변수를 모두 지정해야 한다. 설치 후 파일은 다음 위치에 배치된다.

- 인증서: `/etc/personal-kvm/tls/server.crt` (`0644`)
- 개인키: `/etc/personal-kvm/tls/server.key` (`root:pkvm`, `0640`)

인증서를 지정하지 않으면 설치 스크립트가 365일 자체서명 인증서를 생성한다. 자체서명 인증서는 시험용이며 브라우저 경고가 발생한다.

### 4.2 인증서 자동 갱신

`pkvm-tls-renew.timer`가 매일 인증서 만료를 검사한다. 기본적으로 30일 이내 만료 시 자체서명 인증서를 다시 만든다. 공인 인증서는 `/etc/personal-kvm/.env`에 갱신 명령을 설정한다.

```dotenv
PKVM_TLS_RENEW_DAYS=30
PKVM_TLS_RENEW_COMMAND=/usr/local/sbin/renew-pkvm-certificate
```

갱신 명령은 최종 인증서와 키를 각각 `/etc/personal-kvm/tls/server.crt`, `/etc/personal-kvm/tls/server.key`에 원자적으로 배치해야 한다. 갱신 후 스크립트가 `nginx -t`와 reload를 수행한다.

```bash
systemctl list-timers pkvm-tls-renew.timer
sudo systemctl start pkvm-tls-renew.service
sudo journalctl -u pkvm-tls-renew.service --no-pager
```

## 5. 설치

### 5.1 권장 설치 명령

프로젝트 루트에서 실행한다.

```bash
cd /path/to/personal-kvm-service-v0.0.6

read -rsp '초기 관리자 비밀번호: ' PKVM_ADMIN_PASS
echo
export PKVM_ADMIN_PASS
export PKVM_ADMIN_USER='pkvm-admin'
export PKVM_PHYS_NIC='enp3s0'
export PKVM_HOST_BR_IP='192.168.0.6/24'
export PKVM_HOST_BR_GW='192.168.0.1'
export PKVM_TLS_CERT='/secure/path/server.crt'
export PKVM_TLS_KEY='/secure/path/server.key'

sudo --preserve-env=PKVM_ADMIN_USER,PKVM_ADMIN_PASS,PKVM_PHYS_NIC,PKVM_HOST_BR_IP,PKVM_HOST_BR_GW,PKVM_TLS_CERT,PKVM_TLS_KEY \
  ./scripts/install.sh

unset PKVM_ADMIN_PASS
```

TLS 인증서를 지정하지 않는 시험 설치에서는 마지막 두 변수와 `--preserve-env` 목록의 TLS 항목을 뺀다.

설치 스크립트가 자동으로 수행하는 작업:

1. Rocky 버전, CPU 가상화, 디스크 공간 검사
2. KVM/libvirt/MySQL/Nginx/Python/게스트 도구 설치
3. 비root `pkvm` 서비스 계정과 SSH 키 생성
4. 스토리지·환경파일·TLS 인증서 배치
5. 4개 네트워크와 IP 풀 구성
6. MySQL DB/계정, Alembic 스키마, 관리자 계정 초기화
7. 백엔드, Nginx, TLS 갱신 timer 기동

### 5.2 자동 생성된 초기 비밀번호

`PKVM_ADMIN_PASS`를 지정하지 않으면 난수 비밀번호가 생성되어 다음 파일에 저장된다.

```bash
sudo cat /etc/personal-kvm/.initial_admin_password
sudo stat -c '%U:%G %a %n' /etc/personal-kvm/.initial_admin_password
```

이 파일은 `0600`이어야 한다. 최초 비밀번호 변경이 끝나면 삭제한다.

```bash
sudo rm -f /etc/personal-kvm/.initial_admin_password
```

## 6. 설치 후 필수 검증

```bash
sudo systemctl is-active pkvm-backend nginx libvirtd mysqld
sudo systemctl status pkvm-backend --no-pager
sudo systemctl show pkvm-backend -p User -p Group -p NoNewPrivileges -p ProtectSystem
sudo -u pkvm virsh -c qemu:///system uri
sudo ss -lntp
curl --fail --insecure https://127.0.0.1/api/health
```

정상 보안 상태:

- `pkvm-backend` 실행 사용자는 `pkvm`
- Nginx는 외부 `443`, 필요 시 `80`/`8080`에서 수신
- `80`/`8080` 요청은 HTTPS로 전환
- 백엔드 `8000`은 `127.0.0.1`에서만 수신
- 외부 호스트에서 `http://HOST_IP:8000` 접속 실패

방화벽 확인:

```bash
sudo firewall-cmd --list-ports
sudo firewall-cmd --list-services
```

`8000/tcp`가 외부 허용 목록에 있으면 제거한다.

```bash
sudo firewall-cmd --permanent --remove-port=8000/tcp
sudo firewall-cmd --reload
```

## 7. 최초 로그인과 비밀번호 변경

브라우저에서 다음 주소로 접속한다.

```text
https://호스트주소/
```

1. 설치 시 지정한 관리자 아이디와 초기 비밀번호로 로그인한다.
2. 최초 로그인에서 표시되는 비밀번호 변경 입력창에 새 비밀번호를 입력한다.
3. 대시보드가 나타나는지 확인한다.
4. 자동 생성 초기 비밀번호 파일이 있으면 삭제한다.

API로 변경해야 할 경우:

```bash
read -rsp '현재 비밀번호: ' CURRENT_PASSWORD; echo
read -rsp '새 비밀번호: ' NEW_PASSWORD; echo

TOKEN="$(curl --silent --show-error --insecure https://127.0.0.1/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  --data "$(jq -nc --arg u 'pkvm-admin' --arg p "$CURRENT_PASSWORD" '{username:$u,password:$p}')" | jq -r .access_token)"

curl --fail --silent --show-error --insecure https://127.0.0.1/api/v1/auth/change-password \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  --data "$(jq -nc --arg c "$CURRENT_PASSWORD" --arg n "$NEW_PASSWORD" '{current_password:$c,new_password:$n}')"

unset CURRENT_PASSWORD NEW_PASSWORD TOKEN
```

`--insecure`는 자체서명 인증서 시험 환경에서만 사용한다. 공인 인증서 운영 환경에서는 제거한다.

## 8. 환경파일 관리

운영 환경파일은 `/etc/personal-kvm/.env`이며 권한은 `root:pkvm 0640`이어야 한다.

```bash
sudo stat -c '%U:%G %a %n' /etc/personal-kvm/.env
sudo sed -E 's/^(DB_PASSWORD|JWT_SECRET_KEY)=.*/\1=***REDACTED***/; s#(mysql\+pymysql://[^:]+:)[^@]+#\1***REDACTED***#' /etc/personal-kvm/.env
```

주요 항목:

```dotenv
DATABASE_URL=mysql+pymysql://pkvm_user:DB비밀번호@127.0.0.1:3306/personal_kvm?charset=utf8mb4
DB_PASSWORD=DATABASE_URL과_같은_DB비밀번호
JWT_SECRET_KEY=충분히_긴_난수
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=720
LIBVIRT_DEFAULT_URI=qemu:///system
CONFIG_YAML_PATH=/etc/personal-kvm/config.yaml
FRONTEND_DIST_DIR=/opt/personal-kvm/frontend/dist
QEMU_EMULATOR_PATH=/usr/libexec/qemu-kvm
CORS_ALLOWED_ORIGINS=https://kvm.example.com
```

- `CORS_ALLOWED_ORIGINS`는 쉼표로 여러 출처를 지정할 수 있다.
- 출처에는 경로를 넣지 않고 마지막 `/`를 생략한다.
- credential 정책 때문에 `*`는 허용되지 않는다.
- 같은 Nginx 주소에서 UI와 API를 제공하면 빈 값으로 두어 same-origin만 허용할 수 있다.
- 설정 변경 후 `sudo systemctl restart pkvm-backend`를 실행한다.

### 8.1 DB 비밀번호 변경

DB 비밀번호는 MySQL 계정과 `.env`의 두 위치를 한 작업으로 변경해야 한다. 먼저 DB를 백업한다.

```bash
sudo mysqldump -u root --single-transaction personal_kvm > /root/personal_kvm_before_password_change.sql
NEW_DB_PASSWORD="$(openssl rand -hex 24)"
sudo mysql -u root <<SQL
ALTER USER 'pkvm_user'@'127.0.0.1' IDENTIFIED BY '${NEW_DB_PASSWORD}';
ALTER USER 'pkvm_user'@'localhost' IDENTIFIED BY '${NEW_DB_PASSWORD}';
FLUSH PRIVILEGES;
SQL
```

이후 `/etc/personal-kvm/.env`의 `DB_PASSWORD`와 `DATABASE_URL`을 동일한 값으로 수정하고 서비스를 재시작한다. 비밀번호에 `@`, `:`, `/`, `%`, `?`, `#` 같은 URL 예약문자가 있으면 `DATABASE_URL`에는 URL 인코딩된 값을 사용해야 한다.

```bash
sudo systemctl restart pkvm-backend
sudo journalctl -u pkvm-backend -n 100 --no-pager
unset NEW_DB_PASSWORD
```

### 8.2 JWT 키 교체

JWT 키를 교체하면 기존 로그인 토큰이 모두 무효화된다. 유지보수 시간에 실행한다.

```bash
NEW_JWT_SECRET="$(openssl rand -hex 48)"
sudoedit /etc/personal-kvm/.env
sudo systemctl restart pkvm-backend
unset NEW_JWT_SECRET
```

`JWT_SECRET_KEY`에 새 값을 입력한 뒤 재시작하고 다시 로그인한다.

## 9. 기본 사용 순서

1. **OS 이미지** 메뉴에서 Rocky 8.10/9.8/10 또는 Ubuntu 22.04/24.04 이미지를 업데이트한다.
2. 이미지 상태가 `READY`인지 확인한다.
3. **인스턴스** 메뉴에서 `+ 인스턴스 생성`을 선택한다.
4. OS 이미지 → 이름 → VCore → 메모리 → 네트워크 → 루트볼륨 → 추가볼륨 순서로 입력한다.
5. 생성 후 상태와 Public/Private/Management IP를 확인한다.
6. 인스턴스 작업은 상태에 따라 시작, 중지, 크기 조정, 삭제를 사용한다.
7. 별도 볼륨은 **디스크** 메뉴에서 생성하고, 중지된 인스턴스에 연결·분리한다.

입력 범위:

- VCore: 1~4
- 메모리: 1~8GB
- 루트볼륨: 10~100GB
- 추가볼륨: 0 또는 10~100GB
- 네트워크: Public(NAT/BRIDGED) 또는 내부서비스망 중 하나 이상 필수, 관리망 선택

## 10. 운영 점검과 로그

```bash
sudo journalctl -u pkvm-backend -f
sudo journalctl -u nginx -n 100 --no-pager
sudo journalctl -u libvirtd -n 100 --no-pager
sudo virsh -c qemu:///system list --all
sudo virsh -c qemu:///system net-list --all
sudo systemctl list-timers pkvm-tls-renew.timer
sudo /opt/personal-kvm/backend/venv/bin/alembic -c /opt/personal-kvm/backend/alembic.ini current
```

배포본에 포함된 인수 점검은 격리 호스트에서만 실행한다.

```bash
sudo PKVM_EVIDENCE_DIR=/var/tmp/pkvm-evidence ./scripts/acceptance.sh preflight
sudo PKVM_ACCEPT_DESTRUCTIVE=YES PKVM_EVIDENCE_DIR=/var/tmp/pkvm-evidence ./scripts/acceptance.sh postinstall
```

`postreboot`, `preuninstall`, `postuninstall` 단계도 시스템 상태를 변경하거나 제거 절차와 함께 사용되므로 운영 서버에서 임의 실행하지 않는다.

## 11. 백업

정기적으로 다음 항목을 함께 백업한다.

- MySQL `personal_kvm` 데이터베이스
- `/etc/personal-kvm/config.yaml`
- `/etc/personal-kvm/.env` — 반드시 암호화된 비밀 저장소에 보관
- `/etc/personal-kvm/tls`
- `/data/images`, `/data/instances`, `/data2/disks`
- `/var/lib/personal-kvm/.ssh`

예시:

```bash
sudo mysqldump -u root --single-transaction personal_kvm | gzip > /secure-backup/personal_kvm.sql.gz
sudo tar -C / -czf /secure-backup/personal-kvm-config.tgz etc/personal-kvm var/lib/personal-kvm/.ssh
```

DB와 디스크 파일의 시점이 맞아야 완전한 복구가 가능하다. 운영 VM의 디스크 백업은 정지 또는 스냅샷 정책을 별도로 수립한다.

## 12. 제거

제거 스크립트는 실행 중인 VM이 있으면 중단한다.

```bash
sudo virsh -c qemu:///system list --all
sudo ./scripts/uninstall.sh
```

제거 시 다음 작업이 수행된다.

- 관리 VM과 libvirt 네트워크 해제
- 관리 스토리지의 이미지·인스턴스·추가 디스크 삭제
- DB 상태 정리 및 `/var/lib/personal-kvm/uninstall-audit`에 `0600` 감사 덤프 생성
- DB와 DB 계정 제거
- systemd/Nginx/NetworkManager/패키지 상태 복원
- `/opt/personal-kvm`, `/etc/personal-kvm`, `pkvm` 사용자 제거

중요 데이터는 제거 전에 반드시 별도 백업하고 복원 시험까지 완료한다.

## 13. 자주 발생하는 문제

### 백엔드가 시작되지 않음

```bash
sudo systemctl status pkvm-backend --no-pager
sudo journalctl -u pkvm-backend -n 200 --no-pager
sudo -u pkvm test -r /etc/personal-kvm/.env
sudo -u pkvm virsh -c qemu:///system uri
```

### `일치하는 인수가 없습니다: cloud-utils`

Rocky Linux 9/10은 Ubuntu 계열의 `cloud-utils` 패키지명을 제공하지 않는다. 수정된 설치 스크립트는 `cloud-utils` 대신 EPEL의 `genisoimage`를 설치하고 이를 이용해 NoCloud seed ISO를 만든다.

```bash
sudo dnf install -y epel-release
sudo dnf install -y genisoimage cloud-utils-growpart
command -v genisoimage
sudo ./scripts/install.sh
```

이전 배포본의 `scripts/install.sh`에 `cloud-utils`가 남아 있다면 최신 파일로 교체한 뒤 재실행한다. 설치 스크립트는 실패 체크포인트를 보존하므로 처음부터 안전하게 재실행할 수 있다.

### QEMU emulator 오류

```bash
command -v qemu-kvm || command -v qemu-system-x86_64
sudo virsh -c qemu:///system domcapabilities --arch x86_64 --virttype kvm | grep -A1 '<path>'
grep '^QEMU_EMULATOR_PATH=' /etc/personal-kvm/.env
```

설정된 경로는 실제 실행 가능한 파일이어야 한다.

### HTTPS 인증서 오류

```bash
sudo nginx -t
sudo openssl x509 -in /etc/personal-kvm/tls/server.crt -noout -subject -issuer -dates
sudo openssl x509 -noout -modulus -in /etc/personal-kvm/tls/server.crt | openssl sha256
sudo openssl rsa -noout -modulus -in /etc/personal-kvm/tls/server.key | openssl sha256
```

두 해시가 같아야 인증서와 개인키가 한 쌍이다.

### 브리지 적용 후 네트워크 단절

호스트 콘솔에서 다음을 확인한다.

```bash
nmcli connection show
ip -brief address
ip route
sudo journalctl -u NetworkManager -n 200 --no-pager
```

설치 실패 시 `/var/lib/personal-kvm/install-state`의 백업과 `failed-stage` 기록을 확인한다.
