# Personal KVM v0.1.9: 서버 설치·디버깅 검증 가이드

> 상태: **서버 설치 및 결함 재현을 위한 후보 버전**. 본 버전의 개발 환경 자동검증은 별도 기록하며 Rocky 9.8/10.x 실기기 인수시험은 **미실시**입니다. 이 문서의 절차를 따라 실제 운영 전 시험 서버에서 확인해야 합니다.

## 1. 설치 전 주의

- **격리된 시험용 Rocky Linux 9.8 또는 10.x KVM 호스트**를 사용하십시오. 설치 스크립트는 NetworkManager 브리지, libvirt, nginx, DB, SELinux, 방화벽 등 실제 시스템 설정을 변경합니다.
- 브리지 변경 시 원격 SSH 접속이 끊길 수 있으므로 **콘솔/IPMI/하이퍼바이저 화면**으로 접근 가능한지 먼저 확인하십시오.
- 기존 libvirt VM·스토리지·BIND9·nginx 운영 호스트에서 무조건 실행하지 마십시오. 기존 데이터가 있는 호스트는 별도 백업·영향도 검토 후 진행합니다.
- `PKVM_SETUP_BIND9=1`은 명시적으로 지정한 경우에만 DNS 설치·설정을 시작합니다. L4/L7 데이터평면 역시 별도 설정입니다.

## 2. 패키지 획득 및 검증

```bash
git clone https://github.com/byung8lim/personal_kvm.git
cd personal_kvm
git log -1 --oneline
python3 -m compileall -q backend scripts tests
bash -n scripts/install.sh scripts/setup_lb.sh scripts/diagnose.sh scripts/uninstall.sh
```

릴리스는 GitHub `main`의 v0.1.9 커밋을 기준으로 가져오십시오. 복제 전에 최신 코드/커밋을 확인하고, 호스트의 root 셸 기록에 비밀번호를 입력하지 않습니다.

## 3. 설치 실행

```bash
sudo bash scripts/preflight_check.sh
sudo bash scripts/install.sh
sudo bash scripts/diagnose.sh
```

- `install.sh`는 7단계 처리와 실패한 단계(`/var/lib/personal-kvm/install-state/failed-stage`)를 남깁니다.
- 초기 관리자 비밀번호는 **로그에 출력되지 않으며**, 반드시 서버에서만 다음 명령으로 조회합니다.

```bash
sudo cat /etc/personal-kvm/.initial_admin_password
sudo cat /etc/personal-kvm/install-summary
sudo systemctl status pkvm-backend nginx pkvm-lb-agent --no-pager
curl -kfsS https://127.0.0.1/api/health/ready
```

`/api/health/ready`가 `503`이면 응답 JSON의 `checks`에서 누락된 항목을 확인합니다. 서비스 로그는 다음과 같이 조회하되 **공유하기 전에 비밀정보를 마스킹**하십시오.

```bash
sudo journalctl -u pkvm-backend -n 100 --no-pager
sudo journalctl -u pkvm-lb-agent -n 100 --no-pager
sudo journalctl -u nginx -n 100 --no-pager
```

## 4. L4 HAProxy 및 HA 백엔드 시험

관리자가 서버에서 다음 명령으로 의도적으로 초기화합니다. 실제 리스너/백엔드 IP·포트는 서로 충돌하지 않게 확인하십시오.

```bash
sudo bash /opt/personal-kvm/scripts/setup_lb.sh haproxy 8404
sudo test -S /run/pkvm-lb-agent/control.sock
```

1. 관리 UI에서 Primary/Standby 두 백엔드를 가진 L4 설정을 만들고 **설정 적용**을 누릅니다.
   `sudo systemctl status pkvm-haproxy pkvm-ha-monitor --no-pager`는 **설정 적용 후** 확인합니다.
2. `HAProxy` 설정 파일 `/etc/haproxy/pkvm-managed.cfg`가 생성되었는지, `haproxy -c -f /etc/haproxy/pkvm-managed.cfg`가 성공하는지 확인합니다.
3. UI의 **실시간 상태 확인**에서 실제 `node1/node2` 상태를 읽습니다. 별도의 데이터베이스 상태만으로 성공을 판단하지 않습니다.
4. 시험용 Primary 서비스만 중단하여 지정 횟수 이후 Standby 전환과 `journalctl -u pkvm-ha-monitor`를 확인합니다.
5. Primary를 복구한 뒤 **Primary Failback**을 수동 실행합니다. Standby의 기존 연결이 남으면 기다리고, 30초 안에 종료되지 않으면 기본 설정상 실패로 보고 Standby를 다시 활성화합니다. 기존 세션을 강제로 끊는 기능은 없습니다.

> **주의:** `setup_lb.sh haproxy 8404`의 포트 인자는 설치 인터페이스 호환성을 위한 값입니다. 실제 트래픽 포트는 UI의 L4 정의 `listen_ip:listen_port`에서 지정합니다.

## 5. L7 Traefik 시험

```bash
traefik version  # 3.4 이상 필수
sudo bash /opt/personal-kvm/scripts/setup_lb.sh traefik 8443
sudo systemctl is-active pkvm-traefik
```

UI에서 **wrr/p2c/hrw/leasttime** 설정을 각각 적용해 HTTP 요청 분배를 확인합니다. 테스트에는 복수 백엔드와 여러 요청이 필요합니다. 단일 백엔드만으로 분산 알고리즘이 제대로 작동했다고 판정하지 마십시오. `healthcheck_path`를 지정한 경우 실제 HTTP 2xx/3xx 응답과 장애/복구를 검증하십시오.

참고: [Traefik 공식 HTTP Load Balancer 문서](https://doc.traefik.io/traefik/reference/routing-configuration/http/load-balancing/service/), [v3.4 이후 분산 전략 변경사항](https://doc.traefik.io/traefik/master/migrate/v3/).

## 6. DNS 실시간 정합성 확인

- 관리 UI의 **DNS 실제 A/PTR 레코드 10건 확인**은 DB의 예상값과 Bind9에 대한 실제 `dig` 질의값을 비교합니다.
- 결과 `ok`는 **질의를 실행한 서버에서 확인한 DNS View**에 한정됩니다. Public/Internal/Management Client에서 각자 조회해야 View 검증이 완료됩니다.
- `query_failed`, `conflict`, `missing`, `out_of_zone`은 별도 원인 분석이 필요합니다. 해당 상태를 `ok`로 자동 승격하지 않습니다.

```bash
dig @<DNS_IP> <VM_FQDN> A +short
dig @<DNS_IP> -x <PRIVATE_IP> +short
sudo journalctl -u named -n 100 --no-pager
```

## 7. VM 생성·네트워크 시험 (실환경 필수)

1. 준비된 READY OS 이미지 SHA-256이 확인되는지 검사하고, 계정/암호·NAT 또는 Bridged·내부망을 선택해 VM을 생성합니다.
2. 0개 추가 디스크와 여러 추가 디스크를 **별도로** 시험합니다. UI 작업 현황의 UUID, 단계, 최종 상태를 기록합니다.
3. 호스트에서 각 NIC의 게스트 IP에 `ping`, `ssh`(허용 정책에 따라), `virsh domiflist <VM>`을 대조합니다.
4. 중지/시작/크기변경/삭제 후 디스크·IPAM·libvirt·DNS의 자원 회수를 확인합니다.
5. 가능하면 재부팅 후 동일 상태 확인 및 서비스 자동시작을 수행합니다.

## 8. 테스트 실행 및 증거 등록

```bash
PYTHONPATH=backend python3 -m unittest discover -s backend/tests -p 'test_v019_*.py' -v
python3 -m unittest discover -s tests -p 'test_*.py' -v
sudo PKVM_ACCEPT_DESTRUCTIVE=YES /opt/personal-kvm/scripts/acceptance.sh postinstall
```

마지막 인수 스크립트는 **전용 시험 호스트**에서만 실행하십시오. 버전, 호스트 OS, 커밋 SHA, 실제 명령, 기대/실제 결과, 오류 원문, 서비스 로그를 함께 보존해야 해당 요구사항의 `검증완료` 판정이 가능합니다.

## 9. 현재 남은 확인사항

| 항목 | 코드/자동검사 | 실제 서버 검증 |
|---|---|---|
| LB Agent 설치·소켓 | 설치 스크립트 연결 및 구문 확인 | Rocky 서버에서 service 활성화 필요 |
| HA Failover/Failback·Drain | mock 기반 상태·회복·시간초과 단위 테스트 | 실제 지속 TCP 연결 시험 필요 |
| Traefik 4종 전략·헬스체크 | YAML/버전 파서 단위 테스트 | 설치된 바이너리·트래픽 분배 시험 필요 |
| DNS 실제 A/PTR 비교 | mock 기반 질의 단위 테스트 | named 및 클라이언트별 View 시험 필요 |
| VM·디스크·NIC·libguestfs | 기존 계약 테스트 | Rocky 9.8/10.x 하드웨어 시험 필요 |

이 항목들은 **미시험**이지 자동으로 성공/실패가 확정된 것이 아닙니다.
