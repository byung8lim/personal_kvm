# 퍼스널 KVM 서비스 개요 및 기능 설명서

## 1. 문서 목적

이 문서는 `requirements/개발 구현요청서.md`를 기준으로 퍼스널 KVM 서비스가 최종적으로 제공해야 하는 기능과 동작 방식을 정리한 문서다.

현재 소스의 구현 여부를 설명하는 문서가 아니라, 개발 완료 시 충족해야 할 목표 서비스의 범위와 기능을 명확히 하는 데 목적이 있다. 현재 구현 상태와 차이는 `docs/요구사항_추적조견표.csv`에서 별도로 관리한다.

## 2. 서비스 개요

퍼스널 KVM 서비스는 Rocky Linux 9.8 또는 10.x 호스트 한 대를 KVM 기반 가상화 서버로 구성하고, 관리자가 웹 콘솔에서 가상머신과 관련 자원을 통합 관리할 수 있도록 하는 서비스다.

관리자는 웹 브라우저에서 다음 자원을 관리한다.

- KVM 가상 인스턴스
- 호스트 CPU와 메모리
- 루트 및 추가 가상 디스크
- Bridged, NAT, 내부서비스 및 관리 네트워크
- 네트워크별 IP 주소 풀
- Rocky Linux 및 Ubuntu 클라우드 OS 이미지

서비스는 단순히 DB 화면만 제공하는 관리대장이 아니다. 웹에서 실행한 작업이 실제 libvirt/KVM 도메인, qcow2 디스크 파일, 가상 NIC와 네트워크에 반영되어야 하며, 실제 자원과 DB의 상태가 항상 일치해야 한다.

## 3. 대상 사용자와 접근 방식

### 3.1 대상 사용자

서비스 사용자는 설치 과정에서 설정한 단일 관리자 또는 관리자 권한을 가진 사용자다.

### 3.2 로그인과 접근 통제

- 웹 콘솔은 로그인 후에만 사용할 수 있다.
- 인스턴스, 디스크, 네트워크, IP, 이미지 등 관리 API도 인증된 관리자만 호출할 수 있다.
- 로그인하지 않은 사용자는 로그인 화면 이외의 관리 기능을 사용할 수 없어야 한다.
- 관리자 비밀번호와 인증 키는 소스에 고정하지 않고 설치 환경별로 안전하게 설정·보관해야 한다.

## 4. 시스템 구성

### 4.1 호스트 환경

- 지원 호스트 OS: Rocky Linux 9.8 및 10.x
- 가상화 기술: KVM/QEMU와 libvirt
- 데이터베이스: MySQL
- 백엔드: FastAPI
- 웹 프런트엔드: React
- 웹 프록시: Nginx

### 4.2 주요 저장 위치

기본 구성에서는 자원 유형에 따라 다음 저장 영역을 사용한다.

| 자원 | 기본 경로 | 설명 |
|---|---|---|
| OS 이미지 | `/data/images` | 다운로드하여 등록한 클라우드 이미지 |
| 인스턴스 루트 디스크 | `/data/instances` | 각 VM의 부팅용 디스크 |
| 추가 디스크 | `/data2/disks` | VM 데이터용 추가 볼륨 |

경로와 용량은 구성값으로 관리하고, 화면에 표시하는 용량은 고정값이 아닌 실제 파일시스템 또는 스토리지 풀 상태를 기준으로 계산해야 한다.

## 5. 웹 콘솔 메뉴

웹 콘솔은 다음 주요 메뉴로 구성한다.

1. 대시보드
2. 가상 인스턴스 관리
3. 가상 디스크 관리
4. 가상 네트워크 및 IP 관리
5. OS 이미지 관리

## 6. 대시보드

대시보드는 가상화 호스트와 인스턴스의 핵심 상태를 한 화면에서 확인하는 메뉴다.

### 6.1 호스트 자원 현황

- 전체 VCore와 인스턴스에 할당된 VCore
- 전체 메모리와 인스턴스에 할당된 메모리
- 전체 디스크 용량, 할당 용량 및 가용 용량
- 실행 중, 중지 및 전체 인스턴스 수

표시값은 DB에 기록된 값만 합산해서는 안 되며 실제 호스트와 libvirt 자원 상태를 기준으로 검증해야 한다.

### 6.2 인스턴스 요약 목록

대시보드에는 생성된 인스턴스의 다음 정보를 표시한다.

- 인스턴스 ID
- 인스턴스명
- VCore
- 메모리
- 부트 디스크
- 추가 디스크
- 할당 IP
- 현재 상태

## 7. 가상 인스턴스 관리

### 7.1 인스턴스 생성 위저드

인스턴스 생성은 단계형 팝업 위저드로 제공한다. 기본 진행 순서는 다음과 같다.

1. OS 이미지 선택
2. 인스턴스명 입력
3. VCore 설정
4. 메모리 설정
5. 네트워크 설정
6. 루트볼륨 설정
7. 추가볼륨 설정 및 최종 생성

각 단계는 이전 단계의 입력을 검증한 후 진행하며, 마지막 단계에서 전체 설정을 확인하고 생성 작업을 실행한다.

### 7.2 인스턴스 생성 규칙

| 설정 | 허용 범위 및 규칙 |
|---|---|
| VCore | 1~4 Core |
| 메모리 | 1~8GB |
| 루트볼륨 | 10~100GB, 필수 |
| 추가볼륨 | 10~100GB, 선택 |
| 외부 네트워크 | Bridged 또는 NAT 중 선택 가능 |
| 내부서비스 네트워크 | 서비스 내부 통신용 네트워크 |
| 관리 네트워크 | 선택 사항 |

네트워크 요구사항은 적어도 서비스 통신에 필요한 네트워크가 하나 이상 선택되어야 한다는 의미로 해석한다. Public 계열은 Bridged 또는 NAT 중 선택하고, 내부서비스망과 관리망의 선택 여부를 위저드에서 명확하게 표시해야 한다. 세부 선택 정책이 모호한 경우 실제 구현 전에 발주자와 확정하되, 관리망을 무조건 강제해서는 안 된다.

### 7.3 실제 생성 작업

생성 요청이 승인되면 서비스는 다음 작업을 수행한다.

1. 이름, 자원 범위, 호스트 가용량 및 이미지 상태 검사
2. 필요한 IP와 스토리지 용량 예약
3. 선택 OS 이미지로 루트 qcow2 디스크 생성
4. 필요 시 추가 qcow2 디스크 생성
5. 게스트 OS의 호스트명, 사용자, SSH 및 네트워크 구성 적용
6. libvirt 도메인과 가상 NIC 정의
7. 디스크와 NIC 연결
8. VM 시작 및 실제 상태 확인
9. 성공 상태와 실제 자원 정보를 DB에 기록

중간 단계가 실패하면 이미 예약하거나 만든 IP, 디스크, 도메인 및 DB 상태를 이전 상태로 되돌려야 한다.

### 7.4 인스턴스 목록

인스턴스 관리 화면에는 다음 정보를 표시한다.

- ID 및 인스턴스명
- OS 이미지
- VCore와 메모리
- 루트 디스크와 추가 디스크
- Public 또는 NAT IP
- 내부서비스 IP
- 관리 IP
- 실제 실행 상태
- 현재 상태에서 실행 가능한 작업

### 7.5 시작

- 중지 상태인 인스턴스를 실제로 시작한다.
- 이미 실행 중인 인스턴스에는 시작 작업을 표시하거나 허용하지 않는다.
- 시작 성공 여부는 libvirt의 실제 상태로 확인한다.

### 7.6 중지

- 실행 중인 인스턴스에 정상 종료를 요청한다.
- 이미 중지된 인스턴스에는 중지 작업을 표시하거나 허용하지 않는다.
- 일정 시간 안에 종료되지 않을 때의 강제 종료 정책과 경고를 제공해야 한다.

### 7.7 크기 조정

- VCore와 메모리를 허용 범위 안에서 증가 또는 감소시킨다.
- 실행 중인 VM은 먼저 정상적으로 중지해야 한다.
- 호스트 가용량을 확인한 뒤 libvirt 도메인 정의와 DB를 함께 변경한다.
- 변경 실패 시 기존 사양을 유지한다.

### 7.8 삭제

- 실행 중이면 먼저 정상 종료를 수행한다.
- libvirt 도메인을 해제한다.
- 루트 및 추가 디스크의 물리 파일을 삭제하거나 정책에 따라 반환한다.
- 할당된 모든 IP를 IP 풀에 반환한다.
- 스토리지 할당량과 기타 논리 자원을 반환한다.
- 모든 작업이 확인된 후 인스턴스를 삭제 상태로 변경한다.

일부 자원 회수에 실패한 상태를 성공으로 표시해서는 안 되며, 재시도 가능한 오류 상태로 기록해야 한다.

## 8. 가상 디스크 관리

### 8.1 스토리지 현황

- 호스트 또는 스토리지 풀의 전체 용량
- 할당된 디스크 수
- 할당된 전체 용량
- 현재 가용 용량

### 8.2 디스크 상세 목록

- 디스크 ID와 이름
- 역할: 루트 또는 추가볼륨
- 크기
- 실제 파일 경로
- 할당 여부
- 할당된 인스턴스
- 현재 상태

### 8.3 디스크 작업

- 10~100GB 범위의 추가볼륨 생성
- 중지된 인스턴스에 볼륨 할당 및 연결
- 인스턴스에서 볼륨 분리
- 미할당 볼륨 삭제

DB 레코드 생성만으로 작업을 완료한 것으로 처리하지 않는다. 실제 qcow2 파일과 libvirt 장치 구성이 성공해야 한다.

## 9. 가상 네트워크 관리

서비스는 목적이 다른 네 종류의 네트워크를 관리한다.

| 구분 | 기본 브리지 | 목적 |
|---|---|---|
| Bridged | `virbr0` | 물리 네트워크와 직접 연결하여 외부 공유기 또는 네트워크에서 IP 사용 |
| NAT | `virbr1` | 호스트 NAT를 통해 외부 통신 제공 |
| 내부서비스 | `virbr2` | 외부 연결이 없는 인스턴스 간 내부 통신 |
| 관리 | `virbr3` | 공유스토리지, 모니터링 및 관리 통신 |

### 9.1 네트워크 구성 원칙

- 설치 시 물리 NIC, 호스트 IP, 게이트웨이, CIDR 및 IP 풀을 설정할 수 있어야 한다.
- 기존 호스트 네트워크를 변경하기 전에 충돌과 원격 접속 단절 위험을 검사해야 한다.
- 생성한 libvirt 네트워크는 호스트 재부팅 후에도 필요한 상태로 자동 복구되어야 한다.
- DB에 할당한 IP가 실제 게스트 NIC 구성에도 동일하게 적용되어야 한다.

## 10. IP 주소 풀 관리

### 10.1 IP 풀 정의

각 네트워크는 다음 정보를 가진다.

- 네트워크명과 종류
- 브리지명
- CIDR
- 게이트웨이와 DNS
- 할당 시작 및 종료 IP
- 전체, 할당 및 잔여 IP 수

### 10.2 IP 할당과 회수

- 인스턴스 생성 시 사용 가능한 IP를 중복 없이 예약한다.
- 동시에 여러 생성 요청이 들어와도 동일 IP가 중복 할당되지 않아야 한다.
- 풀이 고갈되면 임의의 기본 IP를 사용하지 않고 생성 요청을 실패 처리한다.
- 인스턴스 삭제가 완료되면 IP, 인스턴스 연결 정보 및 할당 일시를 정리한다.

### 10.3 IP 관리 화면

네트워크별 요약 표에는 다음 내용을 표시한다.

- 네트워크
- CIDR
- 할당 수
- 잔여 수

IP 상세 표에는 다음 내용을 표시한다.

- 순번
- 네트워크
- IP 주소
- 할당된 인스턴스
- 인스턴스 상태
- 할당 일시

## 11. OS 이미지 관리

### 11.1 지원 이미지

- Rocky Linux 8.x
- Rocky Linux 9.8
- Rocky Linux 10.x
- Ubuntu 22.x
- Ubuntu 24.x

### 11.2 이미지 업데이트

관리자가 업데이트 버튼을 누르면 백그라운드 작업으로 다음 절차를 수행한다.

1. 공식 공개 저장소에서 지원 배포판의 최신 클라우드 이미지 정보 조회
2. 기존 등록 버전과 비교
3. 필요한 이미지 다운로드
4. 체크섬과 파일 형식 검증
5. 임시파일에서 정식 이미지 경로로 원자적으로 이동
6. DB에 이미지와 배포 정보를 등록

다운로드 중에도 웹 요청이 장시간 점유되지 않아야 하며, 진행·완료·실패 상태를 확인할 수 있어야 한다.

### 11.3 이미지 목록

- Linux 배포판 종류
- 버전
- 이미지 형식
- 파일 크기
- 배포 일시
- 등록 일시
- 다운로드 또는 준비 상태
- 삭제 작업

### 11.4 이미지 삭제

- 현재 인스턴스 생성에 사용 중인지 검사한다.
- 백그라운드 작업으로 물리 이미지 파일을 삭제한다.
- 파일 삭제 성공 후 DB 상태를 삭제로 변경한다.
- 실패 시 원인과 재시도 가능한 상태를 보존한다.

## 12. 자원 및 상태 관리

### 12.1 관리 대상

- 논리 자원: CPU, 메모리, 디스크 할당, NIC, IP
- 물리 자원: OS 이미지 파일, 루트 디스크 파일, 추가 디스크 파일
- 가상화 자원: libvirt 도메인, 네트워크와 가상 NIC

### 12.2 자원 생명주기

서비스는 자원의 생성, 예약, 할당, 실행, 중지, 삭제 및 반환을 상태 전이로 관리한다.

각 작업은 최소한 다음 정보를 남겨야 한다.

- 요청 작업과 대상 자원
- 작업 시작·완료 시간
- 이전 상태와 목표 상태
- 성공 또는 실패 상태
- 실패 원인과 재시도 여부

DB 상태와 실제 KVM 상태가 다르면 이를 숨기지 않고 장애 또는 불일치 상태로 표시하고 복구해야 한다.

## 13. 호스트 재부팅 및 장애 복구

호스트 재부팅이나 갑작스러운 종료 후 서비스가 자동으로 실행되어야 한다.

서비스 시작 시 다음 절차를 수행한다.

1. DB의 인스턴스 희망 상태 확인
2. libvirt에 실제로 존재하는 도메인과 상태 확인
3. 디스크와 네트워크 등 필수 자원 확인
4. 이전 희망 상태가 RUNNING인 정상 인스턴스 시작
5. 이전 희망 상태가 STOPPED인 인스턴스는 중지 유지
6. 복구할 수 없는 인스턴스는 오류 상태와 원인 기록

## 14. 설치 및 초기 구성

설치 프로그램은 다음 작업을 자동화한다.

1. root 권한과 지원 OS 확인
2. CPU 가상화 지원과 KVM 사용 가능 여부 확인
3. 필수 패키지 설치 상태 확인 및 누락 패키지 설치
4. libvirt, MySQL, Nginx 및 백엔드 서비스 구성
5. 스토리지 디렉터리와 권한 구성
6. 네트워크 설정값 검증 및 네트워크 구성
7. 데이터베이스와 관리자 계정 초기화
8. 안전한 환경변수와 비밀값 생성
9. systemd 및 Nginx 서비스 등록
10. 백엔드, 웹, DB와 libvirt의 동작 확인

설치 중 오류가 발생하면 실패 단계와 원인을 명확하게 표시해야 한다. 다시 실행해도 자원이 중복되거나 기존 정상 설정이 손상되지 않아야 한다.

## 15. 서비스 제거 및 원상복구

제거 프로그램의 목표는 애플리케이션 파일만 삭제하는 것이 아니라 서비스가 관리하던 자원을 안전하게 회수하고 가능한 범위에서 설치 전 호스트 상태로 복구하는 것이다.

### 15.1 실행 중 인스턴스 보호

- 실행 중인 VM이 하나라도 있으면 VM 이름과 경고를 표시하고 제거를 중단한다.
- 관리자가 VM을 정상 종료한 뒤 제거를 다시 실행해야 한다.

### 15.2 제거 순서

1. 실행 중 인스턴스 점검
2. 중지된 인스턴스 삭제와 IP·디스크 등 자원 회수
3. 물리 디스크 및 이미지 파일 점검·삭제
4. DB 관리 정보의 삭제 상태 반영 및 정합성 확인
5. 백엔드와 웹 서비스 중지·해제
6. MySQL DB와 전용 계정 정리
7. libvirt 네트워크와 가상화 환경 구성 복원
8. 설치 프로그램이 추가한 파일과 디렉터리 삭제
9. 설치 프로그램이 추가한 패키지와 시스템 설정 복원
10. 필요 시 재부팅 안내 또는 수행

기존 Nginx 설정, 물리 NIC 설정 및 설치 전 존재하던 패키지는 설치 당시 백업·기록한 정보를 기준으로 복원해야 한다.

## 16. 완료 판단 원칙

다음 원칙을 모든 기능의 공통 완료 기준으로 적용한다.

- UI만 있거나 DB 문자열만 변경하는 것은 완료가 아니다.
- 실제 libvirt/KVM 및 물리 파일 작업이 성공해야 한다.
- 실제 상태와 DB 상태가 일치해야 한다.
- 입력값과 자원 가용량을 서버에서 검증해야 한다.
- 중간 실패 시 생성된 자원을 반환하거나 재시도 가능한 상태로 남겨야 한다.
- 인증 없이 관리 작업을 수행할 수 없어야 한다.
- Rocky Linux 9.8과 10.x에서 설치, 핵심 기능, 재부팅 복구 및 제거 시험을 통과해야 한다.
- 자동화 테스트와 실환경 검증 근거가 없는 기능은 최종 완료로 판정하지 않는다.

## 17. 요구사항 해석상 확인이 필요한 사항

원 개발 요청서에서 다음 항목은 구현 전에 정책을 최종 확정할 필요가 있다.

1. 인스턴스 생성 시 내부서비스 네트워크가 항상 필수인지, Public/NAT 또는 내부서비스 중 하나만 선택해도 되는지
2. Bridged 네트워크의 IP를 서비스 IPAM에서 고정 할당할지, 외부 DHCP 서버에서 할당받을지
3. 실행 중 VM 종료가 지연될 때 강제 종료를 자동 수행할지, 관리자 확인을 받을지
4. 독립 추가볼륨을 실행 중 VM에 hot attach할 수 있게 할지, 중지 상태에서만 허용할지
5. 제거 시 DB의 삭제 이력을 보존한 뒤 DB를 제거할지, 별도 백업 파일로 내보낼지
6. 패키지 제거와 호스트 재부팅을 자동 수행할지, 관리자 확인 후 수행할지

위 정책은 핵심 구조를 바꾸지 않는 범위에서 안전한 기본값으로 구현할 수 있으나, 운영 방식에 영향을 주므로 최종 인수 전에 명시적인 합의가 필요하다.
