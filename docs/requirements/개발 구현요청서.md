# 개발 구현 요청서: 퍼스널 KVM 서비스

프로젝트명: 퍼스널 KVM 가상화 서비스

## 1. 프로젝트 개요
Rocky Linux 9.X 및 10.X 환경에서 KVM 가상화 서비스를 제공한다.
FastAPI와 React를 사용하여 가상화 호스트의 전체 자원사용 및 가상화 인스턴스 및 자원 사용현황을 일괄로 볼수 있는 대시보드 메뉴와 
인스턴스 생성/시동/중지/삭제와 VCORE 및 Memory의 스케일업, 디스크볼륨 추가 등의 인스턴스 관리 메뉴
가상호스트 상의 전체 디스크 사이즈, 할당된 디스크 갯수 및 사이즈, 가용한 디스크사이즈 등의 현황, 생성된 디스크 상세목록(아이디, 사이즈, 할당여부, 할당된 인스턴스) 
등을 조회하고 관리할 수 있는 가상디스크관리 메뉴와 가상 네트워크 메뉴, 그 밖에 OS이미지 관리 메뉴로 구성된다.

## 2. 개발 목표 및 기본 원칙

- 사용자 인터페이스는 FastAPI와 React를 사용하여 웹화면을 제공한다.
- 웹화면접속은 설치시 설정된 어드민관리자로 로그인해야한다.
- 대시보드는 다음과 같은 현황을 표시해야한다.
  - VCore 전체 대비 할당, 메모리 전체 대비할당, 디스크 전체대비 할당현황과 같이 가상화호스트의 자원현황
  - 생성된 인스턴스 목록(아이디, 인스턴스명, Core, 메모리, Boot디스크, 추가디스크, IP, 상태)을 표시한다.
- 인스턴스 관리는 다음과 같은 기능(화면)을 제공한다.
  - 인스턴스 생성: 위저드 형식의 팝어뷰를 표시하여 OS선택 -> 인스턴스명입력 -> 코어수 설정(1~4) -> 메모리크기 설정(1G ~ 8G) -> 네트워크설정 -> 루트볼륨설정 -> 추가볼륨 설정 -> 생성
    - 네트워크 설정 시 Public(또는 NAT) 와 내부서비스네트워크 중 필수로 1개 이상 선택, 관리 네트워크 설정은 선택
      관리네트워크)
    - 루트볼륨설정은 최소 10G ~ 100G까지 설정가능하다.
    - 추가볼륨은 선택사항으로 10G ~ 100G까지 설정가능하다.
  - 인스턴스현황 목록
    - 각 인스턴스의 아이디, 인스턴스명, VCore, Memory, Root디스크, 추가디스크, Public IP(Nested 네크워크), Private IP, 상태, 작업(선택박스)을 표시한다.
	- 작업 
	  - 중지 : 동작중인 인스턴스를 중지(Shutdown) 시킨다. (중지중인 인스턴스는 숨김)
	  - 동작 : 중지중인 인스턴스를 동작(Start) 시킨다. (동작중인 인스턴스는 숨김)
	  - 크기조정: 팝업 뷰를 표시하여 VCore(up/down), Memory(up/down)의 크기를 변경한다.
	    (이 작업에 앞서 동작중인 인스턴스는 중지시켜야한다.)
      - 삭제 : 중지된 인스턴스(동작중인 인스턴스는 중지하고)를 삭제하고 모든 자원을 반환한다. 이때 할당된 IP와 디스크를 포함하는 인스턴스의 물리적인 모든 자원을 회수한다.
- 네트워크는 브리지드(호스트 네트워크의 공유기 등으로부터 아이피할당)와 NAT네트워크, 외부와의 연결이 없는 내부서비스 네트워크, 공유스토리지 및 모니터링 등의 목적의 관리네트워크로 구성된다.
  - 각 설치/구성시 네트워크 구성을 위해 네트워크의 IP풀을 정의한다. 서비스는 각 네트워크의 IP풀을 관리하고 인스턴스의 생성/삭제 시 IP풀의 IP의 할당과 회수를 철저하게 관리한다.
  - 네트워크 관리화면은 각각의 네트워크별 IP풀의 할당현황(네트워크, CIDR, 할당수, 잔여수)과 할당된 IP 상세현황을 표형식으로 보여준다.
    (순번, 네트워크, IP, 할당된인스턴스, 인스턴스상태, 할당일시)
- OS이미지 관리는 인스턴스로 생성할수 있는 OS로 Rocky Linux(8.X, 9.X, 10.X)와 Ubuntu(22.X, 24.X)를 지원하며 업데이트 버튼을 선택하면 백그라운드로 공개된 리포지터리로부터 클라우드 이미지를 조회하여 최신 버전을 등록한다.
  - 등록된 OS이미지를 표형식으로 Linux 타입 및 버전별 이미지 목록(Linux 타입, 버전, 이미지형식, 사이즈, 배포일시, 등록일시, 삭제버튼)을 표시한다.
  - 삭제 버튼을 선택하면 백그라운드로 이미지의 물리적인 이미지를 삭제하고 디비상으로 삭제처리한다.

## 3. 자원관리
- 인스턴스를 구성하는 자원은 논리적인자원(CPU, MEMORY, 디스크, NIC와 IP)과 물리적인 파일로 존제하는 자원(디스크 파일) 등의 생성 -> 할당 -> 중지 -> 삭제 -> 반환 등의 
  라이프 사이클을 관리해야한다. 이를 위해 최소의 데이터모델을 설계하여 MySQL DB로 관리한다.
- 호스트의 리부트 또는 갑작스럴 셧다운 후의 리부트 후 서비스의 자동실행 시, 이전의 인스턴스 상태를 확인하고 장애여부를 점검하여 정상적인 인스턴스는 이전상태를 만든다.
  즉, 중지상태 -> 중지, 동작중 -> 동작

## 4. 서비스 설치 및 구성
### 4.1 시스템환경구성
- 최초 설치 프로그램 실행 시 KVM 가상화 서비스에 필요한 패키지 설치 상태를 점검하여 필요한 패키지를 자동 설치하고 가상화 서비스에 필요한 구성을 자동으로 구성한다.
### 4.2 서버환경구성
- 앞서 상술한 가상화 서버를 위한 환경변수를 정의하고 디폴트 구성파일를 제공한다.

## 5. 서비스 삭제
- 삭제 플로우 : 인스턴스 점검 -> 인스턴스 삭제 및 자원 회수 -> 가상화서버 관리공간 점검 -> 물리파일 및 디렉토리 삭제 -> 디비인스턴스 종료 및 디비 언인스톨 ->
               시스템 가상화 환경 구성 초기화 -> 관련 패키지 언인스톨 -> 설치전상태로 복구 -> 리부팅
- Uninstall 프로그램을 실행하면 동작중인 인스턴스를 점검하여 동작중인 인스턴스가 있으면 경고 문구와 함께 종료한다.
  동작중인 인스턴스가 없으면 중지된 모든 인스턴스를 삭제하고 할당된 모든 자원을 반환하고 연관된 물리파일을 모두 삭제한다.
  모든 인스턴스가 반환되면 디비에 관리중인 인스턴스 정보와 자원 정보도 모두 삭제 상태로 변경한다.
